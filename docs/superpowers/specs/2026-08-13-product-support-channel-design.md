# 乐可开源产品帮助与反馈渠道设计

日期：2026-08-13
状态：已批准并实施
适用产品：乐可点名、归个类，以及后续在 lekeopen.com 发布的软件产品

## 1. 背景与目标

当前官网已有 `/contact/` 联系页面，通过 EmailJS 接收业务咨询，并公开 `contact@lekeopen.com`、微信和电话。产品页则主要引导用户前往 GitHub Issue。普通教师和非开发者可能没有 GitHub 账号，也不熟悉 Issue，因此缺少低门槛、结构化、可持续维护的产品支持渠道。

本项目的目标是：在 lekeopen.com 内建立统一的产品帮助与反馈入口，让用户无需 GitHub 账号即可提交安装问题、使用问题、异常反馈和功能建议，同时控制垃圾信息、隐私风险与长期维护成本。

## 2. 范围与边界

### 本期包含

- 新增 `/support/` 产品帮助与反馈页面。
- 乐可点名、归个类产品页增加“使用遇到问题”入口。
- 支持产品、版本、操作系统、问题类型、问题描述和联系方式等结构化字段。
- 通过 Cloudflare Pages Function 接收、校验和转发反馈邮件。
- 接入 Cloudflare Turnstile，并实施基础频率限制和蜜罐字段检查。
- 为每次成功受理生成不含个人信息的反馈编号。
- 邮件发送失败时明确告知用户，并展示备用邮箱。
- 更新隐私说明、SEO、站点地图及相关测试。

### 本期不包含

- 用户注册、登录或 GitHub 账号要求。
- 附件和截图直接上传。
- 聊天、在线客服、自动 AI 回复。
- 工单数据库、用户查询工单状态、管理后台。
- 微信作为唯一受理渠道。
- 将反馈内容自动创建为公开 GitHub Issue。

## 3. 方案比较与结论

### 方案 A：改造现有 `/contact/` 表单

开发量最小，但业务合作咨询与产品售后混在一起，字段和提示难以同时适配两类用户，后续统计与处理也不清晰。

### 方案 B：独立支持页，使用 Cloudflare 服务端接收（推荐）

新增 `/support/`，复用官网视觉和 Cloudflare Pages 架构。Pages Function 负责校验、反垃圾与 KV 限流，Resend 免费方案负责邮件投递，产品页统一跳转到该页面。职责清晰，可逐步升级为工单系统，不需要现在引入数据库，也不需要购买 Workers Paid。

### 方案 C：接入第三方客服或工单 SaaS

能力完整，但会增加订阅费用、第三方数据处理、品牌割裂和运营负担。当前反馈量尚不足以支撑此复杂度。

结论：采用方案 B。保留 `/contact/` 处理业务咨询；`/support/` 专门处理产品使用与反馈。

## 4. 用户入口与页面结构

### 产品页入口

- 在安装帮助或常见问题附近放置主入口：“使用遇到问题？提交反馈”。
- 在页尾支持区域再次提供同一入口，但不重复制造多个不同渠道。
- GitHub Issue 改为次要文案：“开发者与开源贡献者可前往 GitHub Issue”。
- 入口携带产品参数，例如 `/support/?product=leke-picker`，页面自动预选产品，但用户仍可修改。

### `/support/` 页面

页面顺序：

1. 标题与说明：无需 GitHub 账号，预计 1–2 个工作日内回复。
2. 提交前提示：先查阅对应产品 FAQ；紧急问题不承诺即时响应。
3. 结构化反馈表单。
4. 隐私提示与提交状态。
5. 备用渠道：`support@lekeopen.com`；微信仅作为辅助联系渠道。

表单字段：

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| 产品 | 必填 | 乐可点名、归个类、其他 |
| 软件版本 | 建议填写 | 可从产品页参数预填当前版本 |
| 操作系统 | 必填 | Windows 11、Windows 10、Windows 7、macOS、在线版、其他 |
| 问题类型 | 必填 | 安装、使用、异常、功能建议、其他 |
| 问题描述 | 必填 | 20–3000 字，提示写清操作步骤、预期与实际结果 |
| 联系方式 | 必填 | 优先邮箱；允许手机号或微信号，但明确回复方式可能不同 |
| 称呼 | 选填 | 最多 50 字 |
| 隐私确认 | 必填 | 确认未提交学生名单、真实姓名、私人文件或其他敏感信息 |

本期不允许附件。若需要截图，支持人员在首次回复后通过邮件索取。这样避免恶意文件、对象存储、病毒扫描和敏感信息清理问题。

## 5. 技术架构与数据流

```text
产品页 / Support 页面
        │
        ├─ 客户端基础校验
        ├─ Turnstile 人机验证
        ▼
POST /api/support
        │
        ├─ Origin、Content-Type、大小与字段校验
        ├─ 蜜罐检查与频率限制
        ├─ 生成反馈编号
        └─ 服务端邮件投递
              ├─ 成功：返回编号与受理提示
              └─ 失败：返回可重试错误与备用邮箱
```

- 前端只保存填写中的临时状态，不写入 localStorage。
- Pages Function 不记录完整表单正文到应用日志。
- 邮件接收地址使用 `support@lekeopen.com`，与业务咨询邮箱分离。
- Resend API Key 只放在 Cloudflare 服务端 Secret，不进入 Vite 构建产物。
- 本期不保存数据库副本；邮件系统是唯一受理记录。后续反馈量增长时再评估 D1 工单表。
- 反馈编号格式为 `LK-YYYYMMDD-XXXXXXXX`，随机部分不可枚举，编号不包含产品、电话或邮箱。

现有 EmailJS 客户端表单继续服务 `/contact/`，本项目不顺带重构它。产品支持使用新的服务端路径，避免公开客户端标识、弱化反滥用能力或把两类邮件混在一起。

## 6. 安全、隐私与反垃圾

- Cloudflare Turnstile 必须在服务端验证；仅前端显示验证码不算有效保护。
- 限制请求正文大小，拒绝未知字段、HTML 和可执行内容。
- 文本按纯文本发送，邮件模板进行转义，防止 HTML/邮件注入。
- 校验 `Origin`，只接受官网生产域名和明确配置的预览域名。
- 按隐私友好的客户端标识实施短周期频率限制；不在页面公开具体阈值。
- 使用隐藏蜜罐字段拦截基础机器人。
- 日志只保留结果、反馈编号、时间和错误类别；不得写入问题正文、联系方式或 Turnstile token。
- 页面明确提醒不要提交学生名单、学生姓名、私人文件、密码、密钥或身份证件信息。
- 隐私政策补充反馈数据的用途、处理方式、保留原则和联系方式。

## 7. 成功、失败与降级体验

### 成功

只有服务端确认邮件投递服务已接受请求后，页面才显示“提交成功”，同时显示反馈编号和预计回复时间。表单成功后清空敏感字段。

### 可重试失败

网络超时或邮件服务暂时不可用时，不显示成功；保留用户已填写内容，提示稍后重试，并展示 `support@lekeopen.com`。

### 校验与限流失败

字段错误就近显示；Turnstile 失败提示重新验证；频率受限时提示稍后再试，不泄露内部规则。

### 配置缺失

生产环境缺少 Turnstile 或邮件 Secret 时，API 明确失败并由部署验收阻止发布，不能静默丢失反馈。

## 8. 邮件处理规则

邮件主题统一为：`[产品反馈][产品名][问题类型] 反馈编号`。

邮件正文包含：反馈编号、提交时间、产品、版本、操作系统、问题类型、称呼、联系方式和问题描述。所有用户输入均按纯文本处理。

回复时由支持人员直接联系用户。若用户只留下微信或电话，邮件中明确标识联系方式类型。产品建议是否进入公开 Issue 由维护人员人工判断，并在去除个人信息后处理，不做自动公开同步。

## 9. 可维护性与未来升级

表单字段、产品列表和问题类型使用共享配置，产品页只传递产品标识，避免每个产品复制一套表单。API 的校验、邮件投递和限流分别封装，便于替换邮件供应商。

以下条件出现后再考虑 D1 工单系统：

- 月反馈量持续超过人工邮件可管理范围；
- 需要多人协作、状态跟踪或服务时限统计；
- 用户确实需要凭反馈编号查询进度。

升级时保持 `/support/` 和 `/api/support` 的对外接口稳定。

## 10. 测试与发布验收

### 自动测试

- 字段边界、未知字段、正文大小和 HTML 转义。
- 产品参数预填与无效参数回退。
- Turnstile 成功、失败、超时和重复 token。
- 蜜罐、限流、邮件成功与邮件失败。
- 成功状态只能在服务端确认投递后出现。
- 产品页入口、Support 页面 SEO、canonical、站点地图和静态输出。
- 日志不得包含联系方式、正文或 Secret。

### 人工验收

- 桌面端和移动端完成一次真实提交并收到邮件。
- 验证邮件主题、字段、中文内容和反馈编号。
- 模拟邮件失败，确认页面不会误报成功且备用邮箱可见。
- 验证 Turnstile、键盘操作、表单错误提示和重复提交保护。
- Cloudflare 预览通过后再合并；生产部署后执行只读页面、API、SEO 和日志验收。

## 11. 发布与回滚

发布前需人工完成：

- 创建或确认 `support@lekeopen.com` 可收信。
- 在 Cloudflare 配置 Turnstile、KV 与 Resend API Key Secret；Cloudflare Workers 保持免费套餐。
- 在预览环境发送真实测试邮件。

采用功能开关控制产品页入口。若生产邮件投递异常，可关闭表单并保留 FAQ 和备用邮箱，不需要回滚产品页其他内容。不得在验收过程中执行百度、IndexNow 或其他搜索平台真实提交。

## 12. 验收标准

- 普通用户无需 GitHub 账号即可提交反馈。
- 两个产品页均能正确预选产品并进入 `/support/`。
- 真实反馈可以到达专用支持邮箱，并带有唯一反馈编号。
- 垃圾提交具备 Turnstile、蜜罐、服务端校验和频率限制四层基础防护。
- 投递失败不误报成功，用户始终能看到备用联系渠道。
- 不上传附件，不持久化反馈正文，不在日志中泄露个人信息。
- 完整测试、Cloudflare 预览、生产部署和只读线上验收均通过。
