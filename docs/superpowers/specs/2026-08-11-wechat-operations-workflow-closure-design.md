# 公众号运营工作流收尾设计

## 背景

公众号文章《从官网 Markdown 到公众号草稿，我们为什么要做自己的运营工具》已经发布，但支撑本次发布的文章源文件、配图、发布清单、本地预览能力和运营文档仍停留在主工作区，尚未形成可追溯的正式提交。V1.4 开始前，需要先把这批同源修改整理为一个可验证、可维护的运营工作流版本。

## 目标

- 将已发布文章及其运营资料作为正式项目资产保存；
- 验证 Markdown 到公众号 HTML/纯文本的渲染行为；
- 为新增的预览与富文本转换能力增加自动化回归测试；
- 清除不属于正式结构的临时文件或链接；
- 完成完整质量门禁后提交、同步并恢复干净工作区；
- 不在本次提交中实现 V1.4 SEO 功能。

## 纳入范围

### 已发布内容资产

- `tools/wechat-admin/articles/2026-08-10-operations-toolchain.md`
- `tools/wechat-admin/articles/2026-08-10-operations-toolchain-publish-checklist.md`
- `public/images/articles/2026-08-10-wechat-content-flow.svg`

文章发布后仍保留 Markdown、配图和发布清单，用于内容复用、审计和后续多平台分发。发布清单中的本地绝对路径需要改成仓库相对路径，避免绑定单台电脑。

### 运营工具与文档

- 保留 `wechat:article:preview` 命令；
- 保留 Markdown 图片、引用、二级/三级标题和斜体渲染；
- 保留公众号运营总入口、内容计划和使用说明；
- 保留 Bark 人工审核交接计划，但不引入自动发布；
- 人工审核继续作为公众号发布的最终门禁。

## 文件结构决策

正式图片统一保存在 `public/images/`。根目录 `images -> public/images` 符号链接只是本地文件预览的兼容手段，不进入仓库。预览渲染器负责把站点绝对图片路径 `/images/...` 转换为生成 HTML 可读取的相对文件路径。

`.wechat-admin-output/` 继续作为本地生成目录，不提交渲染产物。

## 测试设计

新增公众号 CLI 回归测试，直接验证真实命令和输出，而不是只检查源码字符串：

- `article render` 能从示例 Markdown 生成 HTML 与纯文本；
- `/images/...` 在本地 HTML 中转换为可读取的相对路径；
- 二级标题、三级标题、斜体、引用、图片和列表得到正确结构；
- `article preview` 在测试环境中不依赖真实浏览器，并能输出本地预览 URL；
- 未知文章动作和缺失文件继续返回明确错误；
- 发布清单不包含开发机器的绝对路径。

为便于真实测试，CLI 主入口应只在脚本被直接执行时运行，并导出纯函数或可注入的预览打开器。测试不得触发浏览器、微信接口或其他外部副作用。

## 验证与发布

收尾质量门禁依次包括：

1. 公众号工具专项测试；
2. `npm run verify` 全量质量门禁；
3. 文章渲染冒烟测试；
4. `git diff --check`；
5. 确认只包含公众号运营工作流和 V1.4 路线图；
6. 提交并同步 `develop`、`main`；
7. 确认本地与远程分支同步且主工作区干净。

## 风险与边界

- 不自动发布或修改微信公众号后台内容；
- 不把本地生成 HTML、纯文本或机器绝对路径提交到仓库；
- 不删除其他任务产生但用途尚未确认的正式内容；
- 不在本次收尾中接入百度、Google 或 Bing；
- V1.4 在本次提交完成后使用独立分支启动。

## 完成标准

- 已发布文章及配图可从仓库完整重建；
- 新增公众号渲染和预览行为有自动化测试；
- 根目录临时 `images` 链接不再存在；
- 全量验证通过；
- 公众号运营工作流形成独立提交并同步远程；
- 主工作区恢复干净，具备启动 V1.4 的条件。
