## 运营命令与边界

### 确定性质量门禁

```bash
npm run verify
npm run verify:seo-ops
```

`verify:seo-ops` 只执行 URL inventory、关键词校验和本地 SEO 运营测试。CI 不运行在线生产巡检，不读取 provider 凭据，也不执行 URL 提交。

### 生产巡检

```bash
npm run seo:inspect
npm run seo:inspect -- --json
```

巡检只对 `https://lekeopen.com` 发起有界 GET 请求，最多 24 次。它是独立的只读运营命令，可能受生产发布状态和网络波动影响，因此不属于确定性 CI 门禁，也不要求在部署修复前先通过。部署完成后它是显式的生产 release gate。

### URL 清单与提交

```bash
npm run seo:inventory
npm run seo:submit -- baidu --dry-run
npm run seo:submit -- indexnow --dry-run
npm run seo:submit -- indexnow --resubmit https://lekeopen.com/about/ --dry-run
```

省略 `--execute` 时默认为 dry-run；运营记录仍应显式写出 `--dry-run`。dry-run 只显示待提交 canonical URL，不调用 provider，也不更新 `.seo-ops/state.json`。内容实质变化需要重提已经接受的 URL 时，必须使用 `--resubmit <canonical-url>` 显式选择当前 published inventory 中的精确 URL；它仍默认 dry-run，不能绕过单次外部写入审批。

真实写入必须由负责人逐次授权，并把最后一个参数改为 `--execute`：

```bash
npm run seo:submit -- baidu --execute
npm run seo:submit -- indexnow --execute
npm run seo:submit -- indexnow --resubmit https://lekeopen.com/about/ --execute
```

| 环境变量 | 用途 | 保密边界 |
| --- | --- | --- |
| `BAIDU_SITE` | 百度提交站点 | 可公开站点值，但只在受控运营环境配置 |
| `BAIDU_SUBMIT_TOKEN` | 百度 URL 提交授权 | 私密；禁止进入仓库、CI 日志、截图、工单或报告 |
| `INDEXNOW_KEY` | IndexNow 所有权 key | 协议要求公开验证，但仍只在受控构建/运营环境管理 |
| `INDEXNOW_KEY_LOCATION` | 可选的 IndexNow key 文件 URL | 公开的绝对 HTTPS URL；不得含凭据/query/hash，且 host 与路径范围必须覆盖全部提交 URL |
| `BAIDU_SITE_VERIFICATION` | 百度 HTML meta 所有权证明 | 公开验证材料，生产构建变量 |
| `GOOGLE_SITE_VERIFICATION` | Google HTML meta 所有权证明 | 公开验证材料，生产构建变量 |
| `BING_SITE_VERIFICATION` | Bing HTML meta 所有权证明 | 公开验证材料，生产构建变量 |

所有 accepted、rejected、retry-eligible 等逐 URL 脱敏结果都可以写入 gitignored 的 `.seo-ops/state.json`；只有 `accepted-for-processing` 会从普通待提交差集中排除。状态写入使用独占锁保护读—合并—原子替换，后到的失败结果不会覆盖既有 accepted 事实。不要提交 `.seo-ops/` 中任何文件，也不要把删除状态当作撤回或普通重试手段。

真实运行若得到 `rejected`、`retry-eligible` 或 `partial-acceptance`，CLI 会在先保存脱敏逐 URL 结果后以非零状态退出，并只输出 provider、错误分类和重试指引；不会输出原始 provider body 或凭据。百度每请求最多 2,000 个 URL；当前 inventory 为 26 个，达到阈值前必须先实现经过测试的批处理。

### 月度报告

```bash
npm run seo:report -- --input /absolute/path/sanitized-monthly-seo.json --output /absolute/path/monthly-seo-report.md
```

输入只能包含脱敏汇总值；缺失指标保留为 `null`。默认拒绝覆盖已有报告，人工确认后才可加 `--force`。模板见 `docs/seo/monthly-report-template.json`。

## 回滚与事故处理

1. **停止写入：** 不再使用 `--execute`；如果凭据疑似泄露，立即在 provider 端撤销或轮换，并清理受影响的受控环境。
2. **代码/发布回滚：** 回滚 V1.4 部署到上一已验证版本，再运行只读生产巡检。所有权证明变量的撤销需先确认不会破坏仍在使用的平台验证方式。
3. **状态恢复：** 修复 `.seo-ops/state.json` 前先在仓库外备份。只恢复已确认接受的脱敏记录；删除状态会让 URL 重新进入待提交集合。
4. **平台事实：** 已被 provider 接受的 URL 提交无法由本工具撤回；平台接受也不保证抓取或建立索引。
